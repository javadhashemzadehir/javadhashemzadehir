## About

I started in 2019 by collecting syntax. Loops, then frameworks, then whatever was trending that month.

What changed things was building something real enough to break. Once software has users, state, and a deploy pipeline, the question stops being *how do I write this* and becomes *where should this live, what happens when it fails, and who pays for this decision six months from now?*

That pulled me from frontend into full-stack, then into architecture — and lately toward statistics, economics, and game theory. The questions holding my attention stopped being about syntax a while ago.

I also founded **Jahat Digital**, a small team building web products, web applications, and the design and digital strategy around them. It keeps me close to the part of the work where a technical decision and a business consequence turn out to be the same decision.

## How I Think About Software

**Real systems over finished tutorials.** Tutorials teach syntax; keeping something alive with users, state, and a deploy history teaches engineering.

**Understand the problem before adopting the abstraction.** Every tool exists because something hurt — if I can't name that pain, I'm inheriting someone else's solution along with their problem.

**Boring and understandable beats clever.** Clear boundaries and obvious code win, because whoever reads it next has none of the context and all of the consequences.

**Trade-offs are the actual work.** Consistency against latency, flexibility against a schema you can reason about, shipping now against maintaining later — choosing deliberately is most of the job.

> **A system is only as good as the assumptions it still lets you change.**
